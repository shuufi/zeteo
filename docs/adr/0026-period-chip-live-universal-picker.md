# Period chip becomes a live, universal Year/Quarter/Month picker — supersedes the month deep-link

`0005` and `0015` left Period decorative because no real dataset sat behind it. `0025` changes that — Period is now real hierarchical master data, and the only existing way to scope to a single month (clicking a Financial Performance P&L column, which deep-links into VDT Explorer via `?month=Jun`) is a one-off, VDT-Explorer-only mechanism with no equivalent for Year or Quarter. The Context Bar's Period chip becomes the one control for Year/Quarter/Month scope on every screen — Financial Performance, VDT Explorer, Driver Diagnostic — via a shared `?period=<code>` param; the P&L cell links become shortcuts that set the same param rather than a separate code path.

Financial Performance genuinely scopes to the chip too, not just VDT Explorer/Driver Diagnostic: its KPI cards' values and its Income Statement table's totals reflect whatever Year/Quarter/Month is picked. Because its statement table is a grid of month *columns* rather than a single scalar, "scoping" there means narrowing which of the 12 columns show (all 12 for the Year, 3 for a Quarter, 1 for a Month) rather than filtering one number — the frontend derives the visible month-order indices from the picked period and slices both the header row and every data row's monthly array to match. The KPI cards' "YTD" label only reads correctly for the whole year, so it's replaced by the period's own label (e.g. "Revenue Q2") whenever a sub-year period is picked.

The chip's widget is a hand-built accordion dropdown — a plain button (no search input) that opens a popover; each row shows an expand chevron if it has children, and clicking a row both selects that period and (if it has children) expands it in place: Year → click reveals Quarters → click a Quarter reveals its Months. `Autocomplete.svelte`'s searchable pattern (used for the Business chip, per `0015`/`0020`) was tried first but rejected here — its filter-as-you-type behavior matches option text against whatever's already typed in the box, and a pre-filled label like "FY26" hid every Quarter/Month option that didn't share that text. Default selection on load is the Year (whole FY) — matching today's unfiltered full-year view, rather than the arbitrary quarter the old mock defaulted to.

Rejected: keeping the cell-link mechanism as a separate, additional entry point alongside the new chip — two ways to pick a period risks them disagreeing about what's currently selected. Also rejected (initially adopted, then reversed): forcing Financial Performance back to the whole year regardless of the chip's selection — once every other screen genuinely scoped, having this one page silently ignore the chip read as broken rather than deliberate.

**Status**: accepted

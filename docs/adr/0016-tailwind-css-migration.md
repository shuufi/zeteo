# Migrate from CSS-custom-property tokens to Tailwind CSS v4 (default theme), adopt @tailwindplus/elements for flat dropdowns/disclosures

`0003`/`0007`/`0011`/`0012` established a hand-rolled Svelte + CSS-custom-property design system (June-sourced spacing/typography/radius, later re-colored to Tailwind's own indigo/gray via `0011`/`0012`), explicitly rejecting Tailwind CSS and `@tailwindplus/elements` as frameworks even though `app.sample.html` (the reference the shell layout was modeled on) uses both. That rejection is reversed: the app now runs on Tailwind CSS v4 (`@tailwindcss/vite`) using Tailwind's own default theme — not a token-preserving reskin. `colors.css`, `spacing.css`, `radius.css`, `typography.css`, `colors-dark.css`, and `zeteo.css` are deleted; every component's styling is Tailwind utility classes. This also drops the custom Nunito/Inter font pairing for Tailwind's default system-sans stack — the single biggest visual change of the migration, done deliberately, not a side effect.

Dark mode keeps `0009`/`0010`/`0012`'s behavior (OS-detect + manual override wins) unchanged in *logic* — `theme.ts` still owns that decision — but now expresses the effective theme as a single `.dark` class toggled on `<html>` (Tailwind's `darkMode: 'class'` via `@custom-variant dark` in `global.css`) instead of swapping a stylesheet.

`@tailwindplus/elements` (a licensed component library the team holds a paid Tailwind Plus license for) replaces hand-rolled `clickOutside`+`$state` interactivity for NavBar's profile menu (`el-dropdown`/`el-menu`) and mobile panel (`el-disclosure`) — both are flat, non-hierarchical UI the library models natively. `BusinessPicker` is a deliberate carve-out: it keeps its hand-rolled Svelte state (BU→Company accordion tree, async fetch/loading/error/retry) because the library has no tree/grouped-option or async-loading concept — only its CSS moved to Tailwind utilities, same as everywhere else.

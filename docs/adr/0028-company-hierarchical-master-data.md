# Business/Company becomes hierarchical master data — MISC Group → Business Unit → Company, mirroring Period

`gl_fact.company` was a bare string with no backing entity at all — `companies.json` was read straight off disk by `/api/companies`, and `resolve_scope()` special-cased "is this code a BU, or a company inside one" by scanning that nested JSON on every request. Company becomes a real dimension table, `company_node` (`code`, `parent_code`, `node_type`, `order`, `is_sampled`), self-referencing the same adjacency-list + type-discriminator shape as `gl_node` and `period`: a new synthetic root, MISC Group (`MISC`), parents the 5 existing Business Units, which parent their Companies. `gl_fact.company` becomes a foreign key into `company_node.code`, matching the FK treatment `period_code` already got in `0025`.

`companies.json` keeps its original nested shape unchanged — it's now pure source data (the real BU/company names), the same role `anaplan_is_master_data.csv` plays for `gl_node`. `seed.py` reads it once to build the flat `company_node` rows, synthesising the MISC Group row the same way it synthesises `period`'s Year row. `is_sampled` (first 3 companies per BU, per `0024`) becomes a persisted column instead of "first 3 in array order," since row order isn't a meaningful DB concept the way list order was in JSON.

`resolve_scope()` (now in a new `company_tree.py`, mirroring `periods.py`'s split from `gl_tree.py`) walks `parent_code` generically for any node — Group, BU, or Company — the same recursive descendant-collection shape `month_indices_for` already used for Period, rather than a hand-rolled per-level branch. Picking MISC Group rolls up every sampled company across all 5 BUs (9 of 86, labelled partial the same way a BU pick already is), extending `0024`'s partial-total concept up one more level. `GET /api/companies` now returns the same flat `{id, label, companyType, parentId, childIds}` shape `GET /api/periods` returns, and the Business chip becomes the same hand-built accordion `PeriodPicker` uses (Group → BU → Company), not the searchable `Autocomplete` it had before — same reasoning as `0026`: a pre-filled input hides everything that doesn't match its own text.

`companies.py` is deleted — nothing needed it once `resolve_scope` and `/api/companies` both moved to querying `company_node` directly.

**Status**: accepted

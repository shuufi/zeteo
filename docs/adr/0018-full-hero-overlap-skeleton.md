# App shell fully adopts app.sample.html's skeleton: -mt-32 overlap card, NavBar lg: breakpoint

`0017` matched `PageHeader`'s color/size to `app.sample.html`'s hero band but explicitly stopped short of the sample's `-mt-32` negative-margin overlap, leaving `ContextBar` and route content in normal flow below the band. A follow-up request asked to make the whole app shell follow the sample skeleton, reversing that scope call.

**Overlap card.** `PageHeader.svelte` gained `pb-32` alongside its existing `bg-indigo-600 dark:bg-indigo-800`/`py-10`, reserving the colored space the overlap pulls into — mirroring the sample's outer `bg-indigo-600 pb-32` wrapper, just scoped to the header alone since `NavBar` is a separate always-colored bar immediately above it (no visible seam, so no need to fold both into one wrapping element). A new shared component, `PageBody.svelte`, centralizes the repeated wrapper every route needs: `<main class="-mt-32"><div class="shell pb-12"><div class="rounded-lg bg-white ... dark:bg-gray-800 ...">{children}</div></div></main>`, matching the sample's rounded overlap card. Extracted as a component per the project's orchestrator/component rule, since the identical wrapper was needed in `Home`, `FinancialPerformance`, `VdtRanked`, `VdtTree`, `DriverDiagnostic`, and `Stub` (used by `NotFound`) — six otherwise-independent route files. Each route's own outer `.shell ...` div was removed since `PageBody` now supplies `.shell` and padding; only the route-specific content classes (`flex flex-col gap-N`, `grid grid-cols-N`, etc.) remain.

**ContextBar placement.** Decided to render inside the card (as the first child, above route content) rather than in the overlap zone as its own row. Its previous full-bleed strip styling (`bg-gray-100`/`dark:bg-gray-900`, its own `border-b`, an inner `.shell` wrapper) no longer made sense once it's living inside a padded white/gray-800 card instead of spanning the page — that outer wrapper and inner `.shell` div were removed, keeping just the flex row of chips/breadcrumb, now with `border-b` + `pb-4` for separation from the content below it within the card.

**Node-not-found branches.** `VdtRanked`, `VdtTree`, and `DriverDiagnostic` each have an `{:else}` branch for an unresolvable `params.id` that previously rendered a bare `<div class="shell ...">` with no `PageHeader` at all. Left as-is, the new `-mt-32` on a bare `PageBody` with nothing above it to reserve the `pb-32` space would pull that content up past the nav bar. Each branch now renders `<PageHeader title="Unknown node" /><PageBody>Unknown node: {params.id}</PageBody>` so the error state keeps the same shell as every real page.

**NavBar breakpoint.** Switched from `md:` to `lg:` throughout, matching the sample's breakpoint, and the logo/nav-links/controls groups were re-nested to match the sample's `flex items-center px-2 lg:px-0` / `hidden lg:ml-10 lg:block` / `hidden lg:ml-4 lg:block` structure. No search input or notification bell were added — Zeteo has no search or notifications feature, so decorative non-functional UI was deliberately left out; only the real content (nav links, theme toggle, profile menu, mobile disclosure) was restructured into the sample's DOM shape.

**Status**: accepted

# POC budget ingestion is a validated script, not an admin UI or medallion pipeline

The POC needs to prove that a dummy-data budget CSV can safely load Financial Budget or Driver Budget facts, but it has neither an authentication/role model nor a governed ingestion platform. `backend/scripts/import_budget.py` will accept a selected four-digit calendar Year, dataset type, and CSV; Financial CSVs use `company_code,year,period,gl_account_code,amount`, while Driver CSVs use `company_code,year,period,driver_code,value`, with period 1–12. It maps source Year/Period values to Zeteo's internal Fiscal Year/Month codes, then uses only rows matching the selected Year. Source is always Budget, and a Driver's unit remains Zeteo master data rather than an import column. `--dry-run` will validate matching rows' structure, reject duplicate Company × code × month rows, and verify supplied Company/Financial/Driver codes against Zeteo's local master data, then report the selected scope's existing budget-row count without writing. `--apply` will require explicit confirmation and, only when validation has passed, atomically delete every existing budget row in the selected Fiscal Year and dataset type before inserting matching file rows. No complete annual coverage matrix is required while POC data is fabricated. The existing application-serving facts remain provisional Gold candidates; no physical Bronze/Silver/Gold tables, budget-version history, restore workflow, or Admin page will be built for the POC. A later UI and production pipeline must define its own completeness and replacement contract rather than inherit this dummy-data exception.

# Reconciliation screen renders one VDT-hierarchy table, not two side-by-side hierarchy trees

ADR-0033 sketched the Reconciliation report as "side by side, Accounting's grouping/total vs VDT's grouping/total for the same node/scope/period" — implying a shared row structure across both hierarchies, and that's how the screen was first built: two Card tables (Accounting, VDT) plus a node picker. Building it out further surfaced a mismatch: only Reporting Root/Reporting Node/Posting GL Account rows (outside the pilot scope) and Posting Activity Account leaves (via their `FA GL` anchor) have a same-code or anchored Accounting counterpart — Activity Node rows, the VDT-only mid-tier, have none. We now render a single table walking the VDT hierarchy (rooted at `V201000000`, VDT Explorer's own anchor — no node picker), three columns per row: VDT amount, Accounting GL amount, Delta (VDT − Accounting). Activity Node rows, including the root, leave GL and Delta blank rather than inventing a rollup — summing anchor GLs would double-count when siblings share one `FA GL` (see Posting Activity Account, ADR-0033), or need dedup logic that manufactures a number nothing in Accounting actually reports. The same reasoning rules out a page-level total: with mid-tier rows blank, any aggregate hits the identical double-count problem, so none is shown — the per-leaf deltas are the diagnostic surface, not a scalar KPI. No color or favourable/adverse scoring on Delta, consistent with ADR-0033's existing stance that the gap is a diagnostic signal, not something to grade.

**Considered and rejected**: side-by-side dual-tree layout (the original implementation) — worked, but doubled the visual scan (matching rows by eye across two trees) instead of putting VDT/GL/Delta together per row, and needed a node picker instead of one agreed-fixed anchor. **Considered and rejected**: rolling up an Activity Node's GL column as the sum of its descendants' unique anchor GLs — produces a number, but not a meaningful "Accounting total for this grouping," since Accounting doesn't group by activity at all.

**Status**: accepted — refines ADR-0033's Reconciliation report paragraph (same non-reconciling philosophy, corrected table shape); ADR-0033 itself stands.
